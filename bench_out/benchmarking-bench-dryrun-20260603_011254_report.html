Here is a basic example of how to structure a job array submission: ```bash sbatch --array=1-10 my_script.sh ``` This will submit 10 tasks (from 1 to 10), where each task runs the same script (`my_script.sh`). Inside your script, you can access the array index using the environment variable `SLURM_ARRAY_TASK_ID`. Example `my_script.sh`: ```bash #!/bin/bash #SBATCH --array=1-10 #SBATCH --time=01:00:00 #SBATCH --nodes=1 echo "Running task $SLURM_ARRAY_TASK_ID on $(hostname)" # Your commands here ``` ### Key Points: - **`--array=start-end`**: Specifies the range of array tasks. - **`--array=start-end:step`**: Specifies a range with a step (e.g., `--array=1-10:2` runs tasks 1, 3, 5, 7, 9). - **`--array=1,5,10`**: Specifies specific task IDs. - **`SLURM_ARRAY_TASK_ID`**: Environment variable available in the script to identify the current task. 🤖 archi's Answer
Based on the FASRC documentation retrieved from the official Slurm documentation, here's what a **job reason code** is: ## What is a Job Reason Code? A **job reason code** is a status indicator used by Slurm to identify why a pending job has not yet been started by the scheduler. When a job is in a pending state, the reason code tells you what is preventing it from running. If there are multiple reasons why a job cannot start, only the reason that was encountered by the attempted scheduling method will be displayed. ## Common Job Reason Codes Here are the most common reason codes you'll encounter: | Reason Code | Meaning | |-------------|---------| | **AssocGrp\*** | The job's association has reached an aggregate limit | | **AssocMax\*** | A portion of the job request exceeds a maximum limit (e.g., PerJob, PerNode) for the requested association | | **BeginTime** | The job's earliest start time has not yet been reached | | **Dependency** | This job has a dependency on another job that has not been satisfied | | **Max*PerAccount** | A portion of the job request exceeds the per-Account limit on the job's QOS | | **Priority** | One or more higher priority jobs exist for the partition associated with the job or for an advanced reservation | | **QOSGrp\*** | The job's QOS has reached an aggregate limit | | **QOSMax\*** | A portion of the job request exceeds a maximum limit on the job's QOS | ## How to View Job Reason Codes You can check the reason code for pending jobs using: ```bash squeue -j ``` The "Reason" column will show you why a job is pending. **Source**: FASRC documentation retrieved from [Slurm Workload Manager Job Reason Codes](https://slurm.schedmd.com/job_reason_codes.html)
✅ Expected Answer
A job reason code in Slurm is a short code that explains why a pending job has not yet started running, such as waiting for resources, priority, dependencies, or other reasons.
