# GPU-only pins, prepended to requirements-base.txt for the PyTorch base image.
#
# torch, vllm and xformers move as ONE unit and cannot be bumped separately:
# vllm pins torch exactly, and xformers ships one build per torch release. Measured
# from PyPI requires_dist on 2026-09-15; tests/unit/test_base_image_dependency_compatibility.py
# holds the constraint tables and fails if this set drifts apart.
#
# vllm was 0.8.5 until 2026-09-15 (#472). That release requires
# opentelemetry-sdk<1.27.0,>=1.26.0, which cannot coexist with the
# opentelemetry-sdk==1.44.0 that requirements-base.txt pins for the OTLP exporter,
# so pip reported ResolutionImpossible and the first v2026.08.0 release build died
# in the build step. Pinning the SDK down to satisfy vllm 0.8.5 is NOT an option:
# the whole <1.27.0 range imports pkg_resources at module scope, which setuptools 82
# removed — see the OpenTelemetry block in requirements-base.txt. vllm 0.9.0 is the
# first release that drops the upper bound, so the bump is the only route that keeps
# both local inference and a working exporter.
#
# torch stays equal to cpu-requirementsHEADER.txt on purpose. The conflict lived
# only here, so the minimal fix would have left the two base images on different
# torch versions while the CPU image serves embedding and reranking.
torch==2.7.0
bitsandbytes==0.46.1
peft==0.5.0
vllm==0.9.0
xformers==0.0.30
